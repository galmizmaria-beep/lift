# Разбор ТЗ «Редактор игры Лифт», версия 1.0

Исходник: `TZ_redaktor_igry_Lift.docx`, предоставлен заказчиком 25 сентября 2026 года. Исходный файл сохранён в рабочей папке без изменений.

## Принятые решения

- Статическое приложение на ES-модулях без обязательной сборки и без backend; размещение в корне GitHub Pages.
- Один движок используется в тестировании и экспортируемой игре. Настройки редактора не входят в игровой интерфейс.
- Число этажей вычисляется по массиву заданий. Ноль в настройке целевого этажа означает автоматический выбор верхнего.
- Состояния игры: титул → холл → вход → готовность → задание → движение → следующее задание / финал. Ошибка не меняет этаж; ноль жизней сразу блокирует продолжение.
- Верный ответ приносит заданные бонусы; частичные бонусы за множественный ответ не позволяют повторно начислять одну и ту же долю за повторную попытку.
- Информационный таймер останавливается на 00:00, а общее затраченное время продолжает учитываться в статистике.
- Текст выводится с экранированием. Данные внутри экспортного script экранируются от закрывающего тега. Проект проверяется до замены текущего состояния.
- Формат `.liftproject`: ZIP с `project.json` и `assets/`. В черновике IndexedDB хранятся реальные Blob, в runtime используются встроенные data URL.
- Облегчённый экспорт минифицирует JS/CSS и JSON, исключает неиспользуемые локали и медиа. Медиа уже оптимизированы при загрузке; повторное сжатие с дополнительной потерей качества не применяется.

## Явные ограничения и упрощения

Базовое разрешение выбирается из трёх форматов 16:9: 1200 × 675, 1600 × 900, 1920 × 1080; произвольного изменения соотношения сторон нет. Параметр направления управляет индикатором; образовательный прогресс всегда идёт от первого задания к последнему. Анимация входа и выхода представлена переходами сцены, дверями и движением героя. Не реализованы необязательный KaTeX, загружаемые аудиофайлы, пользовательские дополнительные условия победы по бонусам и отдельные шаблоны повторного вопроса. После ошибки повторяется то же задание.

Поддержка миграций начинается со схемы 1: новые необязательные поля дополняются значениями по умолчанию, неизвестные версии отклоняются. Формат предыдущих версий не предоставлялся.

Полную сертификацию WCAG 2.2 AA и ручное тестирование во всех браузерах этот выпуск не заявляет. Ключевые игровые сценарии и размеры экранов проверяются автоматизированно.

## Уточнения заказчика — выпуск 1.1

Эти уточнения заменяют соответствующие правила первоначального ТЗ. После ошибки лифт спускается на один этаж, но не ниже стартового. После спуска ученик снова выполняет задание нижнего этапа. Уже полученные бонусы не начисляются повторно.

Сценарий: выбор лифта → открытие дверей → видимый вход персонажа → закрытие дверей → вид из кабины → выбор этажа и отображение цели → старт → задания и движение вверх/вниз. До запуска задания стрелка возврата возвращает к выбору лифта.

Убраны цветок, название на сцене и декоративные полосы. Фон однотонный, с выбором цвета или картинки. Добавлены три локальных SVG-оформления, полноразмерная кабина, центрированная кнопка старта и зелёные пунктирные рамки с перемещением объектов. Положение и масштаб включены в проект и экспорт.

Окно Genially сразу содержит готовый iframe на play.html со снимком игры в URL-фрагменте. «Облегчить код» сжимает ZIP-данные без потерь, показывает экономию и позволяет копировать или скачать код. Свой опубликованный HTML остаётся дополнительным вариантом для больших медиа.
