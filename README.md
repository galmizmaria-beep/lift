# Лифт — мастерская учебных игр

Статический редактор образовательной игры по ТЗ Гальмиз Марии Александровны. Учитель создаёт задания и оформление, ученик поднимается по этажам за правильные ответы.

## Запуск

Онлайн после включения GitHub Pages:

- Редактор: **https://galmizmaria-beep.github.io/lift/**
- Готовая демонстрационная игра: **https://galmizmaria-beep.github.io/lift/demo.html**

В репозитории откройте **Settings → Pages → Build and deployment → Deploy from a branch → main → / (root) → Save**. Дождитесь публикации Pages. Все необходимые файлы уже находятся в корне; сборка для этого способа не требуется.

Локально из папки проекта:

```sh
python3 -m http.server 8000
```

Откройте http://localhost:8000. Сам редактор использует ES-модули и запускается через HTTP. **Экспортированная игра и `demo.html` открываются двойным кликом**, без сервера и интернета.

## Как создать игру

1. В «Проект» задайте название и язык.
2. В «Задания» добавьте вопросы. Один вопрос автоматически создаёт один этаж.
3. Настройте сцену, персонажа, пульт, жизни, таймер и бонусы.
4. Нажмите «Тестировать» и пройдите игру как ученик.
5. «Сохранить проект» создаёт переносимый ZIP-контейнер `.liftproject` с настройками и медиа. «Скачать HTML» создаёт готовую игру.
6. Нажмите «Для Genially»: редактор сразу выдаст готовый iframe с вашей игрой. «Облегчить код» сжимает данные без потери настроек и показывает размеры до/после. Вставьте код через «Вставка → Другие» в Genially. Каждый проект передаётся опубликованному `play.html` в адресе; отдельная публикация HTML для обычного проекта не нужна. Для больших медиа можно использовать свой опубликованный HTML и короткий iframe на его адрес.

При новой сессии редактор предложит восстановить локальный черновик. Изменения хранятся в IndexedDB, медиа — в Blob. Хранилище привязано к браузеру и адресу сайта: для переноса используйте файл проекта.

## Возможности

- 12 разделов настройки, живой предпросмотр, отмена/повтор, выбор лифта, героя и пульта кликом по сцене.
- Пять типов: один ответ, несколько ответов, устная самопроверка/проверка учителем, порядок карточек, текст/число с допуском.
- Дублирование, сортировка и удаление заданий; автоматическая нумерация этажей.
- Оформление лифта выбирается в редакторе. Ученик входит в кабину и выбирает целевой этаж. Правильный ответ поднимает на этаж; ошибка отнимает одну жизнь и оставляет ученика на текущем задании. При достижении цели с оставшейся жизнью показывается победа, при нуле жизней — поражение.
- Жизни, общий/поэтапный таймер, информационный таймер, бонусы за скорость, серию и ответ без ошибки.
- Три оформления лифта, однотонный фон или своя картинка; лифт занимает всю сцену, «Старт» изначально по центру. Объекты выделяются зелёной пунктирной рамкой и перемещаются мышью, касанием или стрелками. Положение и масштаб сохраняются в проекте и экспорте.
- PNG/JPG/WebP автоматически уменьшаются в worker; GIF обрабатываются локальным Gifsicle WASM с сохранением анимации. Если результат больше оригинала, сохраняется оригинал.
- 14 языков системного интерфейса, включая арабский RTL. Авторские тексты не переводятся автоматически.
- Однофайловый автономный HTML; облегчённый вариант с минифицированной игровой логикой и только используемыми медиа/локалями.
- Клавиатура, кнопки ↑/↓ вместо обязательного перетаскивания, видимый фокус и учёт reduced motion.

## Разработка и проверки

Node.js 22+ и npm нужны только для разработки, тестов и пересборки. В опубликованном редакторе нет обязательных внешних запросов или backend.

```sh
npm ci
npm test
npm run build
npx playwright install chromium
# В отдельном терминале: python3 -m http.server 8000
npm run test:e2e
```

`npm run build` обновляет `public/game-runtime.min.js`, автономную демоигру `demo.html` и папку `dist/`. После изменения игровой логики обязательно пересоберите минифицированный runtime перед публикацией.

Браузерный тест поддерживает переменные `BASE_URL`, `PLAYWRIGHT_MODULE` и `CHROME_PATH`. GitHub Actions запускает модульные и браузерные проверки.

## Границы версии 1.1

- Устный ответ подтверждает ученик или присутствующий преподаватель; автоматического распознавания речи нет.
- Тексты формул можно вводить как обычный текст; опциональный KaTeX из ТЗ не включён.
- Пять отдельных звуков (двери, движение, прибытие, верный/неверный ответ) синтезируются в браузере. Есть кнопки прослушивания. Звук требует первого нажатия пользователя; загрузка собственных аудиофайлов не предусмотрена.
- Базовое разрешение выбирается из 1200 × 675, 1600 × 900 и 1920 × 1080 (16:9). На узком экране игровой интерфейс перестраивается вертикально.
- Версия схемы проекта — 1. Неизвестная будущая версия отклоняется без замены текущего черновика; старых выпущенных форматов пока нет.
- Проверки проведены в Chromium на настольном и мобильном размере экрана. Проверка непосредственно в Safari/Firefox и внутри Genially остаётся отдельным этапом совместимости.
- Для больших файлов действуют ограничения: до 50 МБ на изображение, до 100 МБ на архив, до 100 заданий. Чрезмерно большие/повреждённые данные отклоняются.

### Оформление и формулы

- «Кнопки»: отдельные фон, цвет букв и свечение для «Начать», «Войти в лифт», «Старт» и «Проверить».
- «Табло»: фон, цвет и свечение цифр, классический, неоновый или семисегментный вид.
- «Стиль заданий»: 35 системных шрифтов. При отсутствии выбранного шрифта на устройстве браузер использует замену.
- «Этажи и пульт»: собственная формулировка цели; `{floor}` подставляет выбранный этаж.
- LaTeX в вопросах и вариантах ответа: `$...$` в строке, `$$...$$` отдельной формулой. Также поддерживаются `\(...\)` и `\[...\]`. Формулы работают без интернета в экспортированном HTML.
- Исходный вопрос «Что нового ты узнал сегодня?» убран из шаблона и из восстановленных проектов, если это неизменённый последний вопрос шаблона. Пользовательские устные задания сохраняются.

### Защита готовых игр в Genially

Новые ссылки используют неизменяемые проигрыватели `players/v-…/play.html`. В папке каждой версии сохранены логика игры, стили, переводы, загрузчик проекта и библиотеки. Данные конкретной игры по-прежнему находятся внутри её ссылки. Обновления редактора и новые версии проигрывателя не подменяют старые версии.

Старые ссылки `/play.html#project=…`, созданные без номера версии, закреплены за `players/legacy.json`: они сохраняют поведение версии, опубликованной на момент включения этой защиты. До этого все такие ссылки использовали общий меняющийся проигрыватель; исходную историческую версию конкретной игры нельзя определить по ссылке без номера версии.

`npm run build` добавляет новую папку проигрывателя только при изменении его содержимого. Все выпущенные папки должны оставаться в репозитории и на сайте. Манифесты с SHA-256 и проверка GitHub Actions запрещают менять уже выпущенные версии и перенаправление старого адреса. Автор обновляет конкретную игру только явно: создаёт новый iframe и заменяет код в Genially.

Автономные HTML уже содержат собственный код и стили. При использовании собственного адреса HTML его владелец также должен сохранять опубликованный файл по прежнему адресу.
